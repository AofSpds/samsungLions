# SamsungLions 전역 역할 등록부 — v0.1

이 문서는 **도메인 전체에 적용되는 단일 역할 정본**입니다. 프로젝트 안에서 별도의 역할 정의를 임의로 변경하지 않습니다. 역할은 사람/모델/프로세스와 독립적인 책임 단위입니다.

| 코드 | 이름 | 책임 | 결과물 |
| --- | --- | --- | --- |
| `pln` | **총괄(PLN)** | 목표 정리·계획·작업 배정·연구/작업 결과 검토·상태 관리 | 계획, 작업 요청, 검토 결과, 현황 |
| `rsch` | **연구(RSCH)** | 자료 조사·비교·검증 가능한 근거·대안 분석 | 조사·분석 보고, 출처·한계 |
| `pmo` | **범용 작업자(PMO)** | 글·사진·음악·교육자료·앱·스킬 등 실제 제작 및 실행 | `works/` 또는 `apps/`의 작업물, 수행 기록 |

- **사람:** 중요한 결정·수용·공개·외부 공유·파괴적 변경의 최종 승인 주체. Owner는 AI 역할이 아니다.
- **요청 경로:** 사람 → PLN → RSCH 또는 PMO. 명시적으로 지정된 경우 사람 → RSCH/PMO 직접 요청도 가능하며 불필요한 계층을 만들지 않는다.
- **연구와 작업:** 필요하면 병렬로 수행. RSCH는 근거를 보고하고 PMO는 산출물을 생성하며 PLN이 통합·검토한다.
- **결정 권한:** 어떤 AI도 사람의 승인·최종 합의를 만들어내거나 대신 기록하지 않는다.
- **검토:** 별도 검증 역할을 상시 개설하지 않는다. PLN 또는 사람이 요구된 완료 기준에 따라 검토한다.
- **역할 배정:** `SL_ROLE=pln|rsch|pmo` 또는 명시적인 세션 요청으로 정한다. 환경변수 미지정 시 역할은 `unassigned`다. 도메인 역할 *목록*을 이해한다는 것과 현 세션의 *역할을 배정받는 것*은 다르다.
- **프로젝트:** 도메인 역할 등록부는 공통이다. 각 프로젝트의 실제 담당·범위는 `projects/<name>/PLAN.md`에서 정한다.

### 작업 완료 보고(짧게)

**결과 · 근거 · 변경 경로 · 미결 · 다음** 다섯 항목을 사용한다. 완료와 제안을 혼동하지 않는다.
